# Accessibility (a11y) Review & Guidelines

This document tracks the accessibility status of the K8s Dashboard UI and provides guidelines for maintaining an inclusive experience for all users. It addresses [Issue #6](https://github.com/bhf/st-k8s/issues/6).

## 1. Executive Summary

The ST-K8s Dashboard is built with [Next.js](https://nextjs.org/) and [shadcn/ui](https://ui.shadcn.com/), which provides a strong foundation for accessibility. However, custom implementations and specific color choices require ongoing vigilance to ensure compliance with WCAG 2.1 AA standards.

## 2. Review Findings

### 2.1 Color Contrast
*   **Status**: ⚠️ Partial
*   **Observations**:
    *   The application uses `oklch` color spaces.
    *   Dark mode text colors (e.g., `dark:text-[oklch(0.78_0.19_70)]`) in `DashboardContent.tsx` need verification against background colors.
    *   Red error backgrounds (`bg-red-50`, `dark:bg-red-900/20`) need to ensure text within them maintains 4.5:1 contrast.

### 2.2 Keyboard Navigation
*   **Status**: ✅ Good
*   **Observations**:
    *   Interactive elements are primarily standard HTML `<button>` and `<input>` elements.
    *   The command palette (triggered by `:`) provides excellent keyboard-first navigation.
    *   **Action Item**: Ensure the "Grid/List" toggle buttons in the dashboard header show clear focus states.

### 2.3 Screen Reader Support
*   **Status**: ⚠️ Improvement Needed
*   **Observations**:
    *   **Icon-only buttons**: Some buttons, like the chat toggle or view mode switchers, rely on visual icons.
    *   **Loading States**: The spinning loader in `DashboardContent.tsx` is visual-only.
    *   **Tables**: Ensure data tables have proper row headers and captions where applicable.

### 2.4 Focus Management
*   **Status**: ⚠️ Improvement Needed
*   **Observations**:
    *   Focus indicators rely largely on browser defaults or Tailwind's `focus:ring`.
    *   When switching tools, focus should ideally manage to the start of the content area.

## 3. Immediate Remediation Plan (Issue #6)

### High Priority
- [ ] **Icon Buttons**: Add `aria-label` to all buttons that do not have visible text (e.g., View Mode toggles, Chat open button).
- [ ] **Loading Indicators**: Add `role="status"` and `aria-label="Loading..."` to the spinner container in `DashboardContent.tsx`.
- [ ] **Contrast Check**: Audit specific `oklch` values in `DashboardContent.tsx` hardcoded styles.

### Medium Priority
- [ ] **Chat Widget**: Ensure the chat input is labelled (visible or `aria-label`).
- [ ] **Error Messages**: Ensure error alerts use `role="alert"` so screen readers announce them immediately.

## 4. Developer Guidelines

When contributing to the dashboard, follow these simple rules:

1.  **Semantic HTML**: Use `<button>` for actions and `<a>` for navigation. Avoid `div` with `onClick`.
2.  **Labels**: If a button contains only an icon, it MUST have an `aria-label` or `sr-only` text.
    ```tsx
    <Button size="icon" aria-label="Switch to Grid View">
      <GridIcon />
    </Button>
    ```
3.  **Colors**: Prefer semantic variables (e.g., `text-muted-foreground`) over hardcoded hex/oklch values.
4.  **Testing**:
    *   Use the **Tab** key to navigate your new feature. Can you reach everything? Can you see where you are?
    *   Use a screen reader (VoiceOver/NVDA) for complex widgets.
